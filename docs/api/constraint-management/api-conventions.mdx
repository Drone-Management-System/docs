# API Conventions

## Base URL

Routes are registered at the service root. The local default is
`http://localhost:8001`.

## Resource shape

Every record except volume statuses and audit events has:

| Field | Notes |
| --- | --- |
| `id` | UUID generated by the database. |
| `created_at`, `updated_at` | ISO 8601 timestamps. |
| `created_by`, `updated_by` | Actor subject, or `system`. Set by the API, never by the client. |

Reads are **expanded**. Constraints include `volumes_4d`, 4D volumes include
`volume_3d`, `status`, `rule`, and `properties`, and flight corridors include
`gate_area` and `exit_area`. A single read returns everything a map or editor
needs.

## Geometry

Footprints are GeoJSON `Polygon` or `MultiPolygon` geometries in WGS 84, with
coordinates as `[longitude, latitude]`. They are stored as `MultiPolygon` with
SRID 4326, so responses always return `MultiPolygon`. PostGIS rejects invalid
geometries such as self-intersecting rings.

```json
{
  "type": "Polygon",
  "coordinates": [[[55.2708, 25.2048], [55.2808, 25.2048], [55.2808, 25.2148], [55.2708, 25.2148], [55.2708, 25.2048]]]
}
```

## Numbers and times

- Altitudes and buffers are PostgreSQL `numeric`. Send numbers or numeric
  strings; responses return strings such as `"150.00"`.
- Timestamps accept anything JavaScript `Date` parses. Send ISO 8601 with an
  offset.

## Pagination

`limit` (default `50`, `1`–`200`) and `offset` (default `0`, up to `100000`):

```json
{ "items": [], "limit": 50, "offset": 0, "has_more": false }
```

Lists are ordered newest first.

## Filtering

Every resource has `GET <resource>/filter`. Each query parameter is a column
name, optionally with an operator suffix:

```bash
curl "$CONSTRAINT_MANAGEMENT_API_BASE_URL/volumes-4d/filter?status_code__in=%5B%22ACTIVE%22%2C%22SCHEDULED%22%5D&valid_to__gte=2026-06-10" \
  -H "Authorization: Bearer $TOKEN"
```

| Suffix | Meaning | Applies to |
| --- | --- | --- |
| none, `__eq` | Equals | All |
| `__ne` | Not equal | All |
| `__gt`, `__gte`, `__lt`, `__lte` | Comparison | Text, numeric, timestamp |
| `__like`, `__ilike` | SQL pattern (`%`, `_`), case-sensitive or not | Text |
| `__in`, `__not_in` | Value is a JSON array | All except JSON and geometry |
| `__is_null` | `true` or `false` | All |

- JSON columns support only `eq`/`ne`, and take a JSON value.
- Geometry columns support `eq`/`ne` with a GeoJSON polygon, compared with
  `ST_Equals`.
- Timestamps accept a date (`2026-06-10`) or an ISO 8601 timestamp.
- Conditions are combined with AND.
- `all=true` returns every match, with `limit: null`.

## Errors

```json
{ "detail": "no_fly_zones_not_found" }
```

| Status | Pattern | Meaning |
| --- | --- | --- |
| `400` | `<field>_invalid`, or a specific code | Validation failed. Nested fields join their path with `_`, for example `volume_4d_volume_3d_footprint_invalid`. |
| `403` | `permission_denied` | See [Auth and Permissions](./auth-and-permissions). |
| `404` | `<entity>_not_found` | No record has this id. |
| `409` | `<entity>_already_exists` | A unique constraint failed. |
| `409` | `<entity>_has_invalid_reference` | A referenced record does not exist. |
| `409` | `<entity>_has_linked_records` / `resource_has_linked_records` | The record is still referenced. |
| `500` | `internal_server_error` | Unexpected failure. |

Entity names in error codes follow the table names, for example `areas`,
`no_fly_zones`, `volume_4d`, `rules`, and `volueme_3d` (sic) for 3D volumes.

## Cache invalidation

Every write to a constraint, volume, property, or rule clears the cached
[`/constraints` snapshot](./endpoints/snapshot-and-audit). The next read
rebuilds it.
