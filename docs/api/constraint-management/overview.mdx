# Constraint Management API

Constraint Management owns managed airspace constraints, 3D and 4D volumes,
constraint rule metadata, a combined constraint snapshot, and audit logs.

The implementation lives in the sibling project at `../constraint-management`.
Routes are registered at the service root; deployment gateways may add their
own prefix.

## Base URL

When this API is wired into the docs config, use:

```env
DOCS_CONSTRAINT_MANAGEMENT_API_BASE_URL=https://constraint-management-api.example.com
```

Shell examples use:

```bash
export CONSTRAINT_MANAGEMENT_API_BASE_URL="https://constraint-management-api.example.com"
```

## Endpoint Families

| Family | Routes | Purpose |
| --- | --- | --- |
| Health | `GET /health` | Check service readiness. |
| [Airspace constraints](./endpoints/airspace-constraints) | `/areas`, `/monitoring-zones`, `/no-fly-zones`, `/identification-zones`, `/flight-corridors` | Manage named constraints and their 4D volume links. |
| [Volumes and rules](./endpoints/volumes-and-rules) | `/volumes-3d`, `/volumes-4d`, `/rules`, `/rule-types`, `/operator-properties`, `/volume-4d-properties` | Manage geometry, time windows, properties, and rule metadata. |
| [Cache and audit](./endpoints/cache-and-audit) | `/constraints`, `/constraints/refresh`, `/audit-logs` | Publish the combined constraint snapshot and read audit events. |
