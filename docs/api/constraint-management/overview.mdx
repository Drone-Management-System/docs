# Constraint Management API

Constraint Management owns the shape of the airspace: where drones may and may
not fly, when, and under which rules. Operations Intents calls it to check
planned operations against these constraints.

Constraints come in five types: **areas**, **monitoring zones**, **no-fly
zones**, **identification zones**, and **flight corridors** (which run between
two areas). Each is linked to one **4D volume**, a time window over a **3D
volume** (a GeoJSON footprint with altitude bounds). Volumes can carry a
**rule** and typed **properties**. Everything is published as one cached
**snapshot**.

```mermaid
flowchart LR
  C["Constraint<br/>area · zone · corridor"] -- one link --> V4["4D volume<br/>time window, status,<br/>accessibility"]
  V4 -- built on --> V3["3D volume<br/>GeoJSON footprint,<br/>altitude band"]
  V4 -. optional .-> R[Rule]
  V4 -. 0..n .-> P[Properties]
  FC[Flight corridor] -- gate / exit --> A[Areas]
```

The service is Fastify 5 with TypeScript, PostgreSQL with PostGIS through
Drizzle ORM, and optional Redis. Tables live in the
`constraint_management_api` schema.

## Endpoint families

| Family | Base routes | Purpose |
| --- | --- | --- |
| [Airspace constraints](./endpoints/airspace-constraints) | `/areas`, `/monitoring-zones`, `/no-fly-zones`, `/identification-zones`, `/flight-corridors` | Named constraints with their volume. |
| [Volumes](./endpoints/volumes) | `/volumes-3d`, `/volumes-4d`, `/volume-4d-statuses`, `/airspace-constraint-volume-links` | Geometry, time windows, and links. |
| [Volume properties](./endpoints/volume-properties) | `/volume-4d-property-names`, `/volume-4d-properties` | Typed custom fields on 4D volumes. |
| [Rules](./endpoints/rules) | `/rules`, `/rules/bulk` | Rule definitions applied to volumes. |
| [Snapshot and audit](./endpoints/snapshot-and-audit) | `/constraints`, `/audit-logs` | Cached snapshot and write history. |

Every resource also has a `GET <resource>/filter` endpoint for column filters.
