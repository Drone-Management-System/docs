# Rules

Rules describe who may enter a volume. A 4D volume points to at most one rule
through `rule_id`. The rule's `action` (`ALLOW` or `DENY`) overrides the
volume's `default_accessibility` for traffic matching `command`. `PRIMARY` and
`SECONDARY` set precedence for consumers that evaluate several rules.

The API stores `command` as-is; evaluating it is up to consumers such as
Operations Intents. Rules are included in full in the
[constraint snapshot](./snapshot-and-audit).
