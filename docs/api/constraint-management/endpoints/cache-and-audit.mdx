# Cache and Audit

Constraint Management exposes a combined constraint snapshot for consumers that
need all managed airspace constraints in one response.

## `GET /constraints`

<Endpoint
  method="GET"
  path="/constraints"
  title="Read constraint snapshot"
  success="200 OK"
  summary="Returns the combined constraint snapshot from Redis when available, otherwise from the database."
/>

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "$CONSTRAINT_MANAGEMENT_API_BASE_URL/constraints"
```

```json
{
  "source": "redis",
  "cache_key": "constraint-management:constraints:v1",
  "data": {
    "generated_at": "2026-06-30T08:00:00.000Z",
    "constraints": {
      "flight_corridors": [],
      "areas": [],
      "identification_zones": [],
      "no_fly_zones": [],
      "monitoring_zones": []
    }
  }
}
```

`source` can be `redis`, `database_saved_to_redis`, or `database`.

## `POST /constraints/refresh`

<Endpoint
  method="POST"
  path="/constraints/refresh"
  title="Refresh constraint snapshot"
  success="200 OK"
  summary="Rebuilds the snapshot from the database and attempts to save it to Redis."
/>

Create, update, and delete mutations for constraint and volume routes invalidate
the Redis snapshot when cache connectivity is available.

## Audit Logs

`/audit-logs` is a read-only resource route over
`constraint_management_api.audit_log`.

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/audit-logs` | List audit log rows with `limit` and `offset`. |
| `GET` | `/audit-logs/:ID` | Fetch one audit row by `audit_id`. |

## `GET /audit-logs`

<Endpoint
  method="GET"
  path="/audit-logs"
  title="List audit logs"
  success="200 OK"
  summary="Returns paginated audit events ordered newest first."
/>

The route is read-only. It does not expose `POST`, `PUT`, or `DELETE`.
