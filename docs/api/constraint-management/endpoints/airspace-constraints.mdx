# Airspace Constraints

The five constraint types share the same fields, the same six endpoints, and
the same volume handling. Each constraint has a `name`, an `org_id`, and
exactly one linked 4D volume.

## Attaching a volume

Every create needs a volume. Choose one of two forms:

- **Reference:** `"volume_4d_id": "<uuid>"` links an existing 4D volume that is
  not yet linked to another constraint.
- **Inline:** `"volume_4d": { ... }` creates the 4D volume, and its 3D volume
  when `volume_3d` is inline too, in the same transaction.

A permanent volume, such as an airport control zone, has no time window:

<CodeBlock language="json">{JSON.stringify({name: 'Airport control zone', org_id: '8c3198d0-6f9d-4a41-b276-6b60da0bdf54', volume_4d: permanentVolume4dWrite}, null, 2)}</CodeBlock>

On `PUT`, the volume is optional. Sending one replaces the link and deletes the
previously linked 4D volume.

## Ownership

A constraint owns its volumes. Deleting a constraint deletes its 4D volume,
the 3D volume under it, and its properties. Share geometry by copying it, not
by linking one volume to several constraints: the database allows only one
link per volume.
