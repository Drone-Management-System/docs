# API Conventions

Conventions shared by every CAA Registry endpoint.

## Base URL and paths

Routes are registered at the service root, with no version prefix. A gateway
may add its own path prefix; prepend it to every route shown here. The local
default is `http://localhost:8000`.

## Requests

- Send JSON bodies with `Content-Type: application/json`.
- Path ids are UUIDs, except operator and user type ids (smallint) and the
  registration id (string).
- Strings are trimmed. Blank optional strings are stored as `null`.
- Some fields are normalized: emails are lower-cased; country codes and
  organization kinds are upper-cased; national id types are lower-cased.
- Newer resources (Remote IDs, organization admins, custom properties, UA
  aircraft) reject unknown body keys with `payload_invalid`. Older resources
  ignore unknown keys.

## `PUT` is a full replacement

There is no partial update, except `PATCH /users/:userId/national-id`. A `PUT`
body is validated like a create body, and omitted optional fields are set to
`null` or their defaults. Read the record, change what you need, and send the
whole object back.

## Pagination

List endpoints use `limit` and `offset`:

| Parameter | Default | Range |
| --- | --- | --- |
| `limit` | `50` | `1`–`200` (`/audit`: `1`–`500`, default `100`; `/search`: `1`–`50`, default `10`) |
| `offset` | `0` | `0`–`100000` |

```json
{
  "items": [],
  "limit": 50,
  "offset": 0,
  "has_more": false
}
```

`has_more` is `true` when another page exists. Request the next page with
`offset = offset + limit`. There is no total count.

The `/:entity/:id/history` routes are the exception: they return a plain
array, newest first, capped by `limit`.

## Optimistic ownership checks

`PUT` and `DELETE` on `/operators/:operatorId` and `/ua/:uaId` accept
`expected_org_id`, in the query string or in the body:

```bash
curl -X DELETE "$CAA_REGISTRY_API_BASE_URL/ua/$UA_ID?expected_org_id=$ORG_ID" \
  -H "Authorization: Bearer $TOKEN"
```

The write runs only if the record still belongs to that organization, and
otherwise returns `409 expected_org_id_mismatch`. Use it when a UI shows
records for one organization and must not change a record that was moved in
the meantime.

## Errors

Errors always use one shape:

```json
{
  "detail": "organization_not_found"
}
```

`detail` is a stable, machine-readable code. Each endpoint card lists the codes
it can return under **Errors**. Common patterns:

| Status | Pattern | Meaning |
| --- | --- | --- |
| `400` | `<field>_required`, `<field>_invalid` | A field is missing or malformed. |
| `400` | `payload_invalid` | The body is not an object or has unknown keys. |
| `401` | `authentication_required`, `invalid_token` | See [Auth and Permissions](./auth-and-permissions). |
| `403` | `permission_denied` | The token lacks the route's permission. |
| `404` | `<entity>_not_found` | The record, or a referenced record, does not exist. |
| `409` | `<entity>_already_exists`, `*_conflict` | A unique or reference constraint would be violated. |
| `500` | `internal_server_error` | Unexpected failure. Details are only in the service log. |

:::caution[Known gaps]

A few older routes do not map database errors to friendly codes yet, so they
return `500 internal_server_error`:

- A malformed UUID in the path of `GET /organizations/:orgId`, `/users/:userId`,
  or `/operators/:operatorId`.
- A duplicate `org_name`, operator `approval_reference`, or reference data
  `id`/`code`.
- Deleting an organization that still has operators.

Validate these inputs on the client until the service maps them.

:::

## Timestamps and numbers

- Timestamps are ISO 8601 in UTC, for example `2026-05-14T08:00:00.000Z`.
- Remote ID validity timestamps must include an offset and have at most
  millisecond precision.
- Date-only fields, such as operator approval dates, use `YYYY-MM-DD`.
- PostgreSQL `numeric` columns, such as `mass_kg`, are returned as strings to
  keep their precision. They accept numbers or numeric strings on input.

## Audit trail

Every successful write appends a row to `public.audit_log` with the before and
after JSON. Read it through [Audit](./endpoints/audit).
