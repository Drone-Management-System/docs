# Audit

Every write in the registry appends a row to `public.audit_log`, with the full
row before and after the change. Audit endpoints need `audit.read`, which only
`caa_registry_admin` and `caa_registry_auditor` grant.

## Audit event

| Field | Notes |
| --- | --- |
| `audit_id` | UUID. |
| `entity_type` | `organization`, `organization_admin`, `organization_property`, `organization_property_name`, `user`, `operator`, `operator_property`, `operator_property_name`, `ua`, `ua_property`, `ua_property_name`, `remote_id`, `operator_type`, or `user_type`. |
| `entity_id` | The record id, as text. |
| `action` | `create`, `update`, `delete`, `update_national_id`, `zitadel_sync_create`, `zitadel_sync_update`, or `zitadel_sync_delete`. |
| `actor` | Token email, username, or subject, or `system`. |
| `before_json` / `after_json` | Full row snapshots. `before_json` is `null` on create. |

Per-entity history routes are documented with their resources:
[organizations](./organizations#organization-history),
[users](./users#user-history), [operators](./operators#operator-history), and
[UA aircraft](./ua-aircraft#ua-history). For structured audit queries, use
[`POST /audit/filter`](./filters#filter-audit).
