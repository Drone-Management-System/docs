# Custom Properties

Custom properties add typed fields to operators, organizations, and UA aircraft
without schema changes. It works in two steps:

1. **Define** a property once in a catalog, with its name, data type, whether
   it is required or unique, and its allowed values.
2. **Assign** values to individual records. Each value is validated against its
   definition.

The three catalogs share the same API and differ only in paths, id field names,
and permissions:

| Owner | Definitions | Values | Parent field | Permissions |
| --- | --- | --- | --- | --- |
| Operator | `/operator-property-names` | `/operator-properties` | `operator_id` | `operators.*` |
| Organization | `/organization-property-names` | `/organization-properties` | `org_id` | `organizations.*` |
| UA aircraft | `/ua-property-names` | `/ua-properties` | `ua_id` | `ua.*` |

## Data types and domains

Values are always stored as strings and parsed using the definition's
`data_type`:

| `data_type` | Value format | Example |
| --- | --- | --- |
| `string` | Any text | `"STANDARD"` |
| `integer` | Whole number, safe integer range | `"42"` |
| `number` | Finite decimal | `"2.5"` |
| `boolean` | `"true"` or `"false"` | `"true"` |
| `date` | `YYYY-MM-DD` | `"2027-03-31"` |
| `datetime` | ISO 8601 with offset | `"2027-03-31T12:00:00Z"` |
| `json` | Any JSON text | `"{\"bands\":[2.4,5.8]}"` |

`domain_values` restricts what is allowed:

```json
{ "kind": "set", "values": ["BASIC", "STANDARD", "PREMIUM"] }
```

```json
{ "kind": "range", "min": 0, "max": 25 }
```

Ranges work for `integer`, `number`, `date`, and `datetime`. Date bounds can be
relative to the current day, which is useful for expiry dates and age limits:

```json
{ "kind": "range", "min": { "relative": "today" } }
```

```json
{ "kind": "range", "max": { "relative": "today", "years": -18 } }
```

Datetime bounds use `"relative": "now"`. Relative bounds are evaluated at write
time.

## Changing a definition

When a definition's type or domain changes, every stored value is re-checked,
and the update fails with `*_values_conflict` if any value no longer fits.
Turning `is_unique` on fails with `*_duplicates_exist` while any record has
several values. Turning `is_required` on applies to new and changed values
only. Writes to definitions and values are serialized, so these checks are
safe under concurrency.
