# API Conventions

## Base URL

Routes are registered at the service root. The local default is
`http://localhost:8000`.

## Records

Every record except volume links and audit events has `id`, `created_at`,
`updated_at`, `created_by`, and `updated_by`. The actor fields are set by the
API. `PUT` is a full replacement validated like a create.

Reads are expanded: intents include `conops` and `risk_assessment`, and 4D
volumes include `volume_3d`.

## Geometry, numbers, and times

- Footprints are GeoJSON `Polygon` or `MultiPolygon` in WGS 84, stored and
  returned as `MultiPolygon`.
- Altitudes are `numeric`: send numbers or strings, read strings (`"100.00"`).
- Timestamps are ISO 8601. Send an explicit offset.

## Pagination

`limit` (default `50`, `1`–`200`) and `offset` (default `0`):

```json
{ "items": [], "limit": 50, "offset": 0, "has_more": false }
```

## Two error formats

CRUD, package, and volume link routes return the plain format:

```json
{ "detail": "operational_intent_not_found" }
```

Review workflow routes return an envelope with guidance for the user:

```json
{
  "success": false,
  "code": "APPROVAL_STALE_REVIEW",
  "message": "The operational intent changed after the reviewed version.",
  "action": "Run validation again and restart approval review.",
  "details": {},
  "retryable": false,
  "correlation_id": "7f9c2ba4-e88f-4b2a-9d7b-1a2b3c4d5e6f"
}
```

Successful review calls use the same envelope with `success: true` and the
result in `data`. Show `message` and `action` to users as-is; branch on `code`.

## Correlation ids

Review routes read `x-correlation-id`, or generate one, and return it in the
`x-correlation-id` response header and the body. The id is also stored with the
approval decision and audit entry. Send your own to trace a request across
services.

## Validation statuses

| Field | Values |
| --- | --- |
| `overall_status` | `VALID`, `INVALID`, `REQUIRES_REVIEW`, `BLOCKING`, `UNAVAILABLE` |
| `approval_status` | `NOT_REQUESTED`, `PENDING_HUMAN_APPROVAL`, `AUTO_APPROVED`, `HUMAN_APPROVED`, `REJECTED`, `CHANGES_REQUESTED`, `REAPPROVAL_REQUIRED` |
| `decision_type` | `HUMAN`, `RULE_BASED_AUTOMATIC` |
| Finding `severity` | `INFO`, `WARNING`, `ERROR`, `TODO` |
| Finding `category` | `INTENT`, `VOLUME`, `CONOPS`, `RISK`, `CONSTRAINT`, `CONFLICT`, `PERMISSION`, `PRIORITY`, `PRIVILEGE`, `DEPENDENCY` |

The latest validation and approval values are also stored on the intent
(`latest_*_status_code`, `approval_*`), so lists can show them without extra
calls.
