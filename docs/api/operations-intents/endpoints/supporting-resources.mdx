# Supporting Resources

Supporting resources provide the geometry, time, CONOPS, and risk data used by
operational intents and validation.

## Volume Routes

| Resource | Base path | Purpose |
| --- | --- | --- |
| 3D volumes | `/volumes-3d` | Store spatial footprint and altitude band. |
| 4D volumes | `/volumes-4d` | Link a 3D volume to a validity window and status. |

Both routes support standard list, fetch, create, replace, and delete
operations.

## `POST /volumes-3d`

<Endpoint
  method="POST"
  path="/volumes-3d"
  title="Create 3D volume"
  success="201 Created"
  summary="Creates a spatial volume from GeoJSON footprint and altitude bounds."
/>

```json
{
  "name": "Mission footprint",
  "footprint": {
    "type": "Polygon",
    "coordinates": [[[55.25, 25.20], [55.26, 25.20], [55.26, 25.21], [55.25, 25.21], [55.25, 25.20]]]
  },
  "altitude_lower_m": "0",
  "altitude_upper_m": "120",
  "altitude_check": true,
  "altitude_reference_code": "WGS84"
}
```

## `POST /volumes-4d`

<Endpoint
  method="POST"
  path="/volumes-4d"
  title="Create 4D volume"
  success="201 Created"
  summary="Creates a time-bounded volume linked to one 3D volume."
/>

```json
{
  "name": "Mission window",
  "volume_3d_id": "ae530633-4170-4e6f-9138-a2483d39bf56",
  "valid_from": "2026-06-30T08:00:00.000Z",
  "valid_to": "2026-06-30T10:00:00.000Z",
  "status_code": "ACTIVE"
}
```

## CONOPS

`/conops` stores the concept-of-operations narrative used by an operational
intent.

<Endpoint
  method="POST"
  path="/conops"
  title="Create CONOPS"
  success="201 Created"
  summary="Creates the required operational assumptions and procedures record."
/>

All CONOPS write fields are required non-empty strings, including operating
area, operating conditions, RPIC assumptions, crew assumptions, C2 link
assumptions, lost-link procedure, fly-away procedure, emergency procedure, and
detect/see/sense-and-avoid notes.

## Risk Resources

| Resource | Base path | Write body |
| --- | --- | --- |
| Risk assessments | `/risk-assessments` | `name`, `description`, `residual_risk_rating`, `approval_conditions` |
| Risk hazards | `/risk-hazards` | `risk_assessment_id`, `name`, optional `description`, `severity`, `likelihood`, `initial_risk_rating`, `residual_risk_rating` |
| Risk mitigations | `/risk-mitigations` | `hazard_id`, `name`, optional `description`, `verification_method`, `effectiveness_notes` |

Each resource uses the standard CRUD pattern.
