# Operational Intents

An operational intent is a planned flight. The intent row itself is small: a
CONOPS id, a risk assessment id, and the latest validation and approval status.
Its volumes are attached through links.

There are two ways to build one:

- **Package endpoints (recommended).** Send the whole plan in one request,
  with new or existing CONOPS, risk assessment, hazards, mitigations, and
  volumes. Everything is written in one transaction.
- **Resource endpoints.** Create each record separately, then link volumes with
  `/intent-volumes-4d`. This is useful for editors that save one part at a
  time.

## Package references

Every nested item in a package can be:

| Form | Example | Effect |
| --- | --- | --- |
| An id | `"10000000-0000-4000-8000-000000000002"` | Use the existing record. |
| An id object | `{ "id": "10000000-..." }` | Same as an id. |
| A full object | `{ "name": "...", ... }` | Create a new record. |
| A full object with `id` | `{ "id": "...", "name": "...", ... }` | Update that existing record. |

A minimal package only needs volumes:

```json
{ "volumes": ["10000000-0000-4000-8000-000000000004"] }
```
