# Validation and Audit

Operations Intents validation checks whether an operational intent is complete,
has usable volumes, has CONOPS and risk data where required, conflicts with
other operational intents, and intersects managed constraints from Constraint
Management.

## `POST /operational-intents/:id/validate`

<Endpoint
  method="POST"
  path="/operational-intents/:id/validate"
  title="Validate operational intent"
  success="200 OK"
  summary="Runs validation for one operational intent and returns status fields plus findings."
/>

```bash
curl -X POST "$OPERATIONS_INTENTS_API_BASE_URL/operational-intents/26c230de-e661-4bb7-a53d-cfc2f64e3092/validate" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "context": "APPROVAL_REQUEST"
  }'
```

Supported contexts are `CREATE`, `UPDATE`, `APPROVAL_REQUEST`, `ACTIVATION`,
and `REVALIDATION`.

## Validation Stages

| Stage | What it checks |
| --- | --- |
| Intent shape | Required CONOPS and risk references for approval and activation contexts. |
| Linked volumes | At least one 4D volume, valid time ranges, 3D footprint, altitude bounds, altitude reference code. |
| CONOPS | Required narrative fields, with stricter severity for approval and activation. |
| Risk assessment | Residual risk, approval conditions, hazards, and mitigations for approval and activation. |
| Constraint check | Calls Constraint Management `GET /constraints` through `CONSTRAINTS_API_URL`. |
| Internal conflicts | Looks for overlapping volumes in other operational intents. |
| Priority and privilege | Currently returns a TODO finding when conflicts or constrained airspace require review. |

## Constraint Management Integration

The service calls:

```text
GET {CONSTRAINTS_API_URL}/constraints
```

The default value is:

```env
CONSTRAINTS_API_URL=http://localhost:8001
```

If Constraint Management cannot be reached, validation returns
`CONSTRAINT_API_UNAVAILABLE` and sets `constraint_status_code` to
`REQUIRES_REVIEW`.

## Audit Log

`/audit-log` is a read-only resource route over `uss_operations_api.audit_log`.

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/audit-log` | List audit rows with `limit` and `offset`. |
| `GET` | `/audit-log/:ID` | Fetch one audit row by `audit_id`. |
